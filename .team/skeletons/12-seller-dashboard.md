# 12. Панель продавца (`/seller/dashboard`)

Статус: 🔍 согласован

Уровень: **сложный** (JTBD + UX, без CRO — внутренний инструмент)

## Job (JTBD)

- **Функциональный:** «Когда я продавец, я хочу одним взглядом оценить состояние магазина — выручку, заказы, товары — и сразу перейти к действию (обработать заказ, пополнить остатки)»
- **Эмоциональный:** контроль бизнеса «я вижу, что происходит»; Социальный: выглядеть организованным

## Блоки интерфейса

1. **Приветствие** + дата (средний)
2. **Ключевые метрики** (ряд `UCard`): выручка, количество заказов, товаров. Значение крупно, контекст — мелким (`text-xs text-gray-400`). Просмотры/добавления в корзину — НЕ показывать заглушкой: нули/прочерки выглядят как реальные данные и ломают доверие к панели (false signal); появится — добавим честно (высокий)
3. **Свежие заказы** `UDataTable` (5 последних: номер, покупатель, сумма, статус `UBadge`) → `/seller/orders/[id]`; пустая таблица у нового продавца — не мёртвый экран, а подсказка «Заказов пока нет — они появятся, когда покупатели найдут ваши товары» (высокий)
4. **Внимание:** товары с низким остатком / неактивные (badge + список) → `/seller/products` (средний)
5. **Быстрые действия:** «Добавить товар» (`UButton` primary) → `/seller/products/new`, «Все заказы» (ghost) (средний)
6. **Первый запуск:** если у продавца 0 товаров — дашборд заменяется приветственным empty state («Добавьте первый товар») с единственным CTA; нули в метриках новичку не информативны (средний)

## UX-правила

- График тренда — опционально (Sprint 4+); метрики без избыточных графиков в MVP
- Метрики за всё время, без переключателя периода — меньше режимов, меньше ошибок режима (mode error); период добавится вместе с графиками
- Метрики: value крупно (`text-2xl`), label де-эмфазирован (`text-xs uppercase`)
- Один primary CTA на экран («Добавить товар»), остальное ghost
- Сбой API — явный error state с кнопкой «Повторить», не молчаливые нули (ноль — это данные, ошибка — нет)

- **Layout:** dashboard; **middleware:** `seller` (клиент) + проверка роли серверно (`seller-role`)

- **Состояния:** `USkeleton` для метрик и таблицы
- **Ссылки:** входящие — `/seller/products`, `/seller/orders`, header продавца; исходящие — `/seller/orders/[id]`, `/seller/products`, `/seller/products/new`
