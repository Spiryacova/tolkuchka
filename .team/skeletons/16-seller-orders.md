# 16. Заказы продавца (`/seller/orders`)

Статус: 🔍 согласован

Уровень: **сложный** (JTBD + UX)

## Job (JTBD)

- **Функциональный:** «Когда ко мне поступили заказы, я хочу видеть их список и статусы и вовремя обрабатывать, чтобы не потерять клиента»
- **Эмоциональный:** уверенность «ни один заказ не проскочит»
- **Социальный:** — (инструмент)

## Блоки интерфейса

1. **Заголовок** «Заказы» + фильтр по статусу `UTabs` (все / PENDING / CONFIRMED / SHIPPED / DELIVERED / CANCELLED) со **счётчиками** (`UBadge` с числом у каждого статуса) — видно, где ждёт работа, без перещёлкивания табов (высокий)
2. **Таблица** `UDataTable`: номер заказа, покупатель, сумма, дата, статус `UBadge` (семантический цвет), действие «Открыть»; сортировка по дате — новые сверху (высокий)
3. **Пагинация** `UPagination` (средний)
4. **Empty states** — два разных: (а) заказов нет вообще → `UEmpty` «Заказов пока нет» + CTA «Добавить товары» (если нет товаров); (б) пусто по фильтру → «В этом статусе заказов нет» + сброс фильтра (средний)

## UX-правила

- Заказы продавца = заказы, содержащие его `OrderItem` (`OrderItem.sellerId`) — серверный фильтр
- Сумма заказа для продавца = сумма его позиций (не всего заказа!)
- Строка кликабельна → `/seller/orders/[id]`

## Компоненты Nuxt UI

- `UDataTable`, `UTabs`, `UBadge`, `UPagination`, `UButton`, `USkeleton`, `UEmpty`

## Затрагиваемые сущности

- ✅ `Order`, `OrderItem` (sellerId), `Product`, `User` (покупатель)

## Технический каркас

- **Layout:** dashboard; **middleware:** `seller`
- **Рендеринг:** SSR; SEO: `robots: noindex`
- **Состояния:** `USkeleton` строк; empty state
- **Ссылки:** входящие — dashboard (свежие заказы), header продавца; исходящие — `/seller/orders/[id]`
- **API:** `GET /api/sellers/orders?status=`
