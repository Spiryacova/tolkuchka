# 20. Детали заказа (`/account/orders/[id]`)

Статус: 🔍 согласован

Уровень: **средний** (JTBD кратко)

## Job (JTBD)

- «Когда я открыл заказ, я хочу видеть его позиции, статус и адрес доставки, чтобы понимать, что именно и куда едет»

## Блоки интерфейса

1. **Заголовок:** «Заказ №…» + статус `UBadge` (высокий)
2. **Позиции** `UDataTable`, **сгруппированные по продавцам** (подзаголовок «Продавец: {имя}» над позициями каждого — заказ мультивендорный, покупатель видит, что придет несколько отправлений): товар (фото, название → ссылка), количество, цена за единицу, сумма строки (высокий)
3. **Доставка:** адрес из `shippingAddress` (jsonb), дата создания (средний)
4. **Итого** крупно (высокий)
5. **CTA «К списку заказов»** (ghost) → `/account/orders` (низкий)

## UX-правила

- Доступ только владельцу заказа (серверная проверка buyerId — не только клиент)
- Если заказ чужой/не существует → 404 (не показывать данные)
- Цена строки = `priceAtPurchase` (зафиксирована при покупке)

## Компоненты Nuxt UI

- `UCard`, `UDataTable`, `UBadge`, `UButton`, `USkeleton`

## Затрагиваемые сущности

- ✅ `Order`, `OrderItem`, `Product`, `shippingAddress` (jsonb)

## Технический каркас

- **Layout:** default; **middleware:** `auth`
- **Рендеринг:** SSR; SEO: `robots: noindex`
- **Состояния:** `USkeleton`; 404 для чужого/несуществующего заказа
- **Ссылки:** входящие — `/account/orders`; исходящие — `/account/orders`, `/products/[slug]`
- **API:** `GET /api/orders/[id]` (проверка владельца серверно)
