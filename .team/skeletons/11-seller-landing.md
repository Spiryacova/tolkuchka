# 11. Лендинг продавца (`/seller`)

Статус: 🔍 согласован

Уровень: **сложный** (лендинг, JTBD + CRO)

## Job (JTBD)

- **Функциональный:** «Когда я продаю вещи/хобби-товары и хочу расширить охват, я хочу понять, как начать продавать на Толкучке и какой путь с минимальными усилиями, чтобы начать зарабатывать, а не изучать инструкции»
- **Эмоциональный:** уверенность «это просто и безопасно», не чувствовать себя новичком
- **Социальный:** выглядеть как продавец с магазином, а не «выкладывающий на доске объявлений»

**Ключевые возражения (CRO):** «не пойму процесс», «страшно потерять время/деньги», «а вдруг не будет покупателей».

### Силы (Push / Pull / Anxiety / Habit)

| Сила | В чём | Ответ интерфейса |
|------|-------|------------------|
| Push | Комиссии, бюрократия и перегруженные кабинеты крупных МП | «Как это работает» — 3 шага, прозрачные условия |
| Pull | Охват аудитории + «настоящий магазин» со своей ссылкой | Value prop в hero, профиль магазина `/sellers/[slug]` |
| Anxiety | «Не разберусь», «комиссия съест доход», «не будет покупателей» | FAQ, блок условий без мелкого шрифта, простота флоу |
| Habit | Продавать в мессенджерах и на барахолках разовыми объявлениями | Постоянный магазин: товары работают на продавца, а не сутки |

**Конкуренты за job:** доски объявлений, мессенджеры/соцсети, крупные МП, свой сайт. Выигрываем: проще МП, солиднее досок, бесплатнее своего сайта.

**Little Hire:** регистрация с ролью SELLER; метрика — конверсия лендинга в регистрацию (не повторяемость).

> Соцдоказательство («уже продают N продавцов») и ссылка на живой магазин-пример — когда появятся реальные данные (MVP+1), не раньше.

## Блоки интерфейса (по CRO)

1. **Hero** — value prop продавца («Продавайте на Толкучке: без сложностей, заказы к вам сами»), единственный главный CTA «Стать продавцом» → `/auth/register?role=seller` (высокий)
2. **Как это работает** — 3 шага (регистрация → добавление товаров → получение заказов). Снимает «не пойму процесс» (высокий)
3. **Возможности** — карточки: управление товарами, статистика, заказы, профиль магазина (средний)
4. **Комиссия и условия** — прозрачно, без мелкого шрифта. Снимает «страшно по деньгам» (средний). ⚠️ Контент зависит от бизнес-решений, которых ещё нет (комиссия? платежи?): рабочая формулировка — «размещение бесплатное, оплата при получении покупателем»; финальный текст утвердить отдельно (решение команды 2026-08-21: отложено)
5. **FAQ** — `UAccordion`: «сколько стоит», «как получаю оплату», «как устроены возвраты» (средний; ответы — из тех же бизнес-решений, что и блок 4)
6. **Финальный CTA** — повтор «Стать продавцом» + «или сначала посмотрите каталог» (низкий)

## UX-правила

- Один главный CTA повторяется на странице, вторичные — всегда ghost/outline
- CTA ведёт на регистрацию с предвыбранной ролью SELLER (не отдельная форма)
- Если пользователь уже авторизован как SELLER → CTA ведёт в `/seller/dashboard`
- Если авторизован как BUYER → CTA «Стать продавцом» вызывает `POST /api/sellers/become` и ведёт в `/seller/dashboard` (без повторной регистрации)
- Страница prerendered: подстановка CTA по роли происходит на клиенте поверх статического HTML (SSR-состояние auth недоступно)

## Компоненты Nuxt UI

- `UButton` (primary CTA), `UCard` (шаги/возможности), `UAccordion` (FAQ), `Icon` (i-heroicons для шагов)

## Технический каркас

- **Layout:** default; **middleware:** нет (публичный)
- **Рендеринг:** SSR, `routeRules` prerender (статический контент); SEO: `useSeoMeta` (title «Продавайте на Толкучке», description, OG)
- **Состояния:** — (статическая страница)
- **Ссылки:** входящие — AppHeader CTA «Стать продавцом», футер, баннер на `/`, `account/settings` (если BUYER); исходящие — `/auth/register?role=seller`, `/seller/dashboard` (для SELLER)
- **API:** `POST /api/sellers/become` (при необходимости из кабинета BUYER)
