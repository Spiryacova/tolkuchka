# 17. Заказ продавца (`/seller/orders/[id]`)

Статус: 🔍 согласован

Уровень: **средний** (JTBD кратко)

## Job (JTBD)

- «Когда я открыл заказ, я хочу видеть его позиции и адрес покупателя и обновить статус, чтобы заказ двигался к доставке»

## Блоки интерфейса

1. **Заголовок:** «Заказ №…» + статус `UBadge` (высокий)
2. **Позиции** `UDataTable` (только позиции продавца): товар, количество, цена, сумма (высокий)
3. **Покупатель + адрес доставки** (из `shippingAddress` jsonb): `UCard` — имя, email, адрес, **комментарий покупателя** (если оставил — он писал его для продавца) (высокий)
4. **Смена статуса:** `USelect` (только валидные переходы вперёд по `OrderStatus` + отмена; назад — нельзя) + `UButton` «Обновить статус»; сервер валидирует переход, невалидный — 409 (высокий)
5. **Итого** (сумма позиций продавца) крупно (средний)
6. **CTA «К списку заказов»** (ghost) → `/seller/orders` (низкий)

## UX-правила

- Только заказы с позициями текущего продавца; чужой/несуществующий → 404
- Менять статус заказа может продавец только в рамках своей части (в MVP статус заказа общий — фиксируем решение на реализацию #38)
- Переходы статуса ограничены машиной состояний (напр. PENDING → CONFIRMED/CANCELLED, DELIVERED — терминальный); кнопка «Обновить» задизейблена, пока статус не изменён
- Смена статуса — без перезагрузки, тост «Статус обновлён», бейдж в шапке обновляется сразу

## Компоненты Nuxt UI

- `UCard`, `UDataTable`, `UBadge`, `USelect`, `UButton`, `USkeleton`, `useToast`

## Затрагиваемые сущности

- ✅ `Order` (status, shippingAddress), `OrderItem`, `Product`, `User` (покупатель)

## Технический каркас

- **Layout:** dashboard; **middleware:** `seller` (+ владелец позиций серверно)
- **Рендеринг:** SSR; SEO: `robots: noindex`
- **Состояния:** `USkeleton`; 404 для чужого заказа
- **Ссылки:** входящие — `/seller/orders`, dashboard; исходящие — `/seller/orders`, `/products/[slug]`
- **API:** `GET/PATCH /api/sellers/orders/[id]`
