# 09. Оформление (`/checkout`)

Статус: 🔍 согласован

Уровень: **сложный** (JTBD + CRO — финальная воронка)

## Job (JTBD)

- **Функциональный:** «Когда корзина собрана, я хочу ввести данные доставки и подтвердить заказ в 2–3 действия, чтобы не бросить оформление на середине»
- **Эмоциональный:** уверенность «всё понятно, ничего лишнего не спрашивают»
- **Социальный:** — (слабо применим; осознанность выбора поддерживается карточками продавцов в сводке)

### Силы (Push / Pull / Anxiety / Habit)

| Сила | В чём | Ответ интерфейса |
|------|-------|------------------|
| Push | Длинные формы и принудительная регистрация на других площадках | Минимум полей, email предзаполнен, один шаг |
| Pull | Прозрачность: вижу что покупаю и сколько плачу | Сводка заказа рядом с формой, итого крупно |
| Anxiety | «Спишут деньги / не позвонят / адрес не тот» | Строка доверия у CTA, всё редактируемо до подтверждения, возврат в корзину |
| Habit | Купить в мессенджере у продавца без оформления | Один шаг без лишних вопросов — быстрее переписки |

**Конкуренты за job:** оформление в мессенджере/по телефону, офлайн. Выигрывает за счёт скорости (2–3 действия) и записанного состояния заказа.

**Little Hire:** оформление — редкое действие; метрика = завершаемость (доля дошедших до success), а не повторяемость.

## Блоки интерфейса (по CRO)

1. **Breadcrumbs** `UBreadcrumb` (корзина → оформление) (низкий)
2. **Форма доставки** `UForm`: имя, email (предзаполнен из профиля), адрес (`UInput`/`UTextarea`), комментарий (опц.) (высокий)
3. **Сводка заказа** `UCard`: позиции (кратко, ссылки на товары), подытог, **итого** крупно (высокий)
4. **CTA «Подтвердить заказ»** (`UButton` primary, `loading`) — создаёт `Order` (высокий)
5. **Доверие/возврат** — короткая строка «Оплата при получении / возврат в течение 14 дней» (снятие возражений, средний; формулировка валидна, пока онлайн-оплаты нет — при появлении платежей пересмотреть)
6. **Ошибки:** инлайн `UFormGroup` + `useToast` при сбое сервера (средний)

## UX-правила

- Минимум полей: имя, email, адрес — всё остальное не спрашиваем (снижение трения)
- Гость с корзиной (localStorage) при входе на `/checkout` → middleware `auth` отправляет на `/auth/login?redirect=/checkout`; после входа пользователь возвращается, корзина на месте
- Адрес пишется в `shippingAddress` (jsonb) у `Order` — не отдельная модель
- Создание заказа — Prisma-транзакция: валидация корзины, списание stock, создание `Order`+`OrderItem`, очистка корзины (задача #33); проверка `stock` внутри транзакции — иначе гонка двух покупателей
- Если stock закончился во время оформления → API отвечает 409: тост «Товар закончился» + предложение вернуться в корзину
- Если корзина пуста → редирект на `/cart`
- Один подтверждающий шаг (без wizard-многошаговости в MVP)

## Компоненты Nuxt UI

- `UBreadcrumb`, `UForm`, `UFormGroup`, `UInput`, `UTextarea`, `UCard`, `UButton`, `USpinner`

## Затрагиваемые сущности

- ✅ `Order` (создание, `status: PENDING`, `shippingAddress` jsonb), `OrderItem`, `Product` (stock), `CartItem` (очистка), `User`

## Технический каркас

- **Layout:** default; **middleware:** `auth` (+ `?redirect=/checkout` для возврата после логина)
- **Рендеринг:** SSR; SEO: `robots: noindex`
- **Состояния:** `USpinner` в кнопке при сабмите; ошибки инлайн + `useToast`; 409 (stock) — тост + ссылка в корзину
- **Ссылки:** входящие — `/cart`; исходящие — `/checkout/success`, `/cart`, `/products/[slug]`
- **API:** `POST /api/orders` (транзакция, валидация `order.schema.ts`); ответ — `{ id }` заказа → редирект `/checkout/success?orderId=…`

## Сверка с дизайн-системой

- Соответствует. Форма `max-w-lg`, сводка справа (2 колонки desktop); primary CTA полной ширины
- Итог в сводке — `text-2xl font-semibold` (как в корзине, консистентность); строка доверия — `text-sm text-muted` под CTA
- Метки полей де-эмфазированы, обязательные помечены по §5
