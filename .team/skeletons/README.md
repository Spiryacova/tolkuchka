# Каркасы страниц (Page Skeletons)

Каркасы всех страниц проекта — результат проектирования по [DEV-WORKFLOW.md](../DEV-WORKFLOW.md): **JTBD → CRO → сущности + компоненты → refactoring-ui → тех. каркас**.

- [audit-entities.md](./audit-entities.md) — сводный аудит сущностей vs Prisma-схема (главный выход)
- Файлы `NN-*.md` — каркас одной страницы по шаблону артефакта (DEV-WORKFLOW §3)

## Статусы

- ⬜ черновик — скелет создан, требует ревью
- 🔍 согласован — команда утвердила
- ✅ реализован — страница готова в коде

## Как работать со скелетами

Промпт универсальный — применяется ко всем страницам. Меняются только путь к файлу, **тип страницы** (от него зависит шаг 2) и приоритет. Шаги 1, 2, 5 — правки внутри файла скелета (агент действует свободно); шаги 3, 4, 6 — **агент предлагает, разработчик решает**; шаг 7 — решение команды.

```
СТРАНИЦА: .team/skeletons/03-product.md
ТИП: конверсионная | кабинет | простая        ← меняется, от него зависит шаг 2

1. JTBD — СКИЛЛ: jobs-to-be-done
   Проверь/уточни Job (3 измерения). Правишь только текст скелета. Разрешение не нужно.

2. Блоки и CTA — СКИЛЛ: cro  (если тип = конверсионная)
               — СКИЛЛ: design-everyday-things  (если тип = кабинет)
               — БЕЗ СКИЛЛА, пропуск  (если тип = простая)
   Уточни блоки, иерархию, снятие возражений. Разрешение не нужно.

3. Сущности — БЕЗ СКИЛЛА (правило: сверка с audit-entities.md)
   Каждый блок → сущность. Если всплыл ❌ → СТОП и запроси решение разработчика:
   ДОБАВИТЬ в Prisma / ПЕРЕИСПОЛЬЗОВАТЬ / ОТЛОЖИТЬ. Без разрешения схему не менять.

4. Компоненты Nuxt UI — БЕЗ СКИЛЛА (правило: карта DESIGN-SYSTEM §6)
   Блок → компонент. Нет в карте → предложи вариант:
   (а) кастомный доменный компонент — допустим сразу (создаётся в app/components/),
   (б) правка карты DESIGN-SYSTEM — ТОЛЬКО по разрешению, через PR.

5. Визуал — СКИЛЛ: refactoring-ui
   Токены, шкалы 4/8/16/24/32/48/64, семант. цвета, loading/empty/error. Разрешение не нужно.

6. Тех. каркас — БЕЗ СКИЛЛА (чеклист Nuxt)
   Layout / middleware / SSR-ISR / SEO / ссылки / API.
   Если правка влияет на другие страницы (общий layout, routeRules) → согласовать с разработчиком.

7. Статус — АДМИН-ДЕЙСТВИЕ
   ⬜ → 🔍 ставим ТОЛЬКО после согласования скелета с разработчиком.
```

**Применение по группам:**

| Тип страницы | Страницы | Шаг 2 |
|--------------|----------|-------|
| Конверсионная | 01, 02, 03, 04, 05, 07, 08, 09, 11 | `cro` |
| Кабинет | 12–17, 18–20 | `design-everyday-things` |
| Простая / без шага 2 | 06, 10, 21–26 | пропуск шага 2 |

**Правило:** изменения скелета, затрагивающие сущности или карту компонентов, в том же PR обновляют `audit-entities.md` и/или `DESIGN-SYSTEM.md` — иначе доки разъезжаются.
